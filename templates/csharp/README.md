# {{name}}

A self-hosted Ino Loyalty connector for {{platform}}, generated by `ino connector new --lang csharp`. It needs the .NET 10 SDK and has no NuGet dependencies at run time (the tests use xUnit).

## Run
1. `cp .env.example .env`. Fill in the test channel's API key and secret from Power Apps → Settings → Developers → API keys. Never commit `.env`.
2. Run `dotnet test tests/Connector.Tests`, then `dotnet run --project src/Connector`.
3. Subscribe to events: `ino webhooks create --url https://<your-host>/webhooks/ino`. Put the secret it prints in `INO_WEBHOOK_SECRET`.
   While developing locally, use `ino listen --forward-to http://localhost:8080/webhooks/ino` and `ino trigger <type> --forward-to …` instead.

## What is in it
| File | What it does |
|---|---|
| `src/Connector/InoClient.cs` | Signed calls (signature v2). It adds a `requestId` and retries 429/5xx and network errors with the same body and a new nonce. It never retries a 401 and never follows a redirect. |
| `src/Connector/Webhook.cs` | Checks Standard Webhooks signatures on the raw body, with a 5-minute window. |
| `src/Connector/OfflineQueue.cs` | Offline queue. A sale keeps its real time (`transactionDate`) and is sent later, in order. |
| `src/Connector/Program.cs` | `/health`, `/webhooks/ino` (deduplicates on `webhook-id`; ignores test events), and `/platform/order-paid` (replace it with your platform's events). Heartbeat every 5 minutes. |

## Before go-live
Run the scenarios on the test channel, then run `ino connector check --suite ecommerce` (or `--suite pos`). Each scenario has to pass.

## Share it in the connector store
`ino-connector.json` describes the connector. Set `category` (ECOMMERCE or POS), `license`, `repository` (public) and `description`, push, then:

```
ino hub submit --company "<company>" --contact-name "<name>" --contact-email "<address>" --dry-run   # see exactly what is sent
ino hub submit --company "<company>" --contact-name "<name>" --contact-email "<address>" --yes
```

The submission goes to Tryino only. It carries the manifest, the repository, the commit and pass/fail per compatibility scenario, never keys, tenant or channel codes, or customer data. Tryino reviews and tests that exact commit; nothing is published until Tryino approves.
